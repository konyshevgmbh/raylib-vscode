# raylib_button

raylib game/app (C99, raylib fetched by CMake FetchContent). One codebase for Windows, Linux, macOS, Web and Android.

## Structure

- `src/main.c` - main loop, fade transitions between screens, shared `font` and `fxCoin` sound.
- `src/screens.h` - `GameScreen` enum and the Init/Update/Draw/Unload/Finish functions of every screen.
- `src/screen_<name>.c` - one file per screen (currently `title` and `gameplay`).
- `assets/` - loaded with the same relative path `assets/...` on every platform.
- `web/shell.html` - web page template (bare canvas). `android/` - Gradle project. `icons/` - generated by `tools/gen_icons.js`.

A screen reports that it is done through `FinishXScreen()` (returns 0 while running, a non-zero code when it wants
to leave). `main.c` turns that code into `TransitionToScreen(...)`.

## Rules

- Layout comes from `GetScreenWidth()/GetScreenHeight()`, never fixed pixel sizes: the window is resizable and phones are tall.
- Touch is mapped to the mouse on Android/Web, so use mouse/gesture input only.
- New `.c` files in `src/` are picked up automatically (CMake globs `src/*.c`, re-run CMake is not needed).

## Build from a terminal

- Windows: `cmake --preset windows` then `cmake --build --preset windows-debug` (exe: `build-windows/Debug/raylib_button.exe`)
- Linux: `cmake --preset linux` then `cmake --build --preset linux`
- macOS: `cmake --preset macos` then `cmake --build --preset macos`
- Android: `cd android && ./gradlew assembleDebug` (APK: `build-android/gradle/outputs/apk/debug/`)

Run/debug from VS Code with the Raylib Devices extension (status bar: mode, device, run).
